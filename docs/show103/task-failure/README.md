# SHOW-103 과제 실패 판정 수정

실패 정산·즉시 초기화의 대상을 제어기 중단에서 **과제 실패**로 변경했다. `quadratic_release`에만 적용하며, 학습은 진행하지 않았다.

| 판정 | 초기값과 조건 |
|---|---|
| 최초 파지 제한시간 | 빈손·pregrasp 초기화에서 12초 이내 양쪽 손가락 접촉을 연속 100ms 확인하지 못하면 실패 |
| 파지 확인 | 양쪽 손가락과 큐브의 접촉을 연속 100ms 확인. 들어 올리기는 요구하지 않음 |
| 운반 중 그릇 밖 낙하 | 파지 후 들어 올린 이력이 있고, 양쪽 손가락에서 분리되어 탁자에 접촉. 그릇 내부 바닥 지지는 없으며 큐브 속도 ≤20mm/s인 상태가 연속 100ms이면 실패 |
| 들어 올린 이력 | 파지 확인 후 양쪽 손가락 접촉이 유지된 상태에서 큐브 최하단이 탁자보다 5mm 초과 높고 탁자 접촉이 없음. 기존 held 초기화의 실제 carry 판정도 인정 |

- 12초는 20초 에피소드 안에서 접근·재시도를 허용하는 **초기 설정값**이다. 학습을 통한 적정성 평가는 아직 하지 않았다.
- 처음부터 잡고 시작하는 grasp·preinside 초기화에는 최초 파지 제한시간을 적용하지 않는다.
- 최초 파지 전에는 제한시간까지 재시도할 수 있다. 탁자에서 잡았다 놓친 경우도 들어 올린 이력이 없다면 낙하 실패로 종료하지 않는다.
- 파지 확인 이력은 유지한다. 최초 파지 후 탁자에서 재시도하는 경우에는 전체 20초 제한이 적용된다.
- 처음부터 탁자에 놓인 큐브, 공중 낙하 중인 큐브, 그릇 내부 바닥에 착지한 큐브는 낙하 실패가 아니다. 그릇 벽에 걸린 경우는 이번 조기 실패 조건에 추가하지 않았다.

## 정산과 제어기 중단

- 과제 실패 시 해당 스텝의 양의 상태·이벤트 보상은 지급하지 않는다. 실제 발생한 action·action rate·충격·재접촉 비용은 한 번 반영한다.
- 현재 비용 `c=max(미완료·거리 비용, 0.6)`과 남은 스텝의 할인 비용 `c × Σ(0.99^k), k=1..남은 스텝`을 정산하고 즉시 초기화한다. 중복 정산 방지는 유지했다.
- 최초 파지 시간 초과가 12초에 발생하면, 현재 비용과 남은 80스텝 정산은 약 **−33.42점**이다. 해당 스텝의 실제 action 등 비용은 별도다.
- 제어기 보호 중단은 `controller_interruption`으로 별도 기록·종료한다. 과제 실패 정산을 부과하지 않으며, 일반 스텝 보상·비용 처리는 유지한다.
- 물리 NaN·접촉 용량 초과는 기존 RuntimeSafety에서 실행 오류로 처리한다.
- 첫 해제 높이·착지·철수의 기존 보상/성공 조건은 유지했다. 이 수정은 기존 정책을 다시 학습한 결과가 아니다.

## 검증

- CPU: 관련 42개 테스트 통과. 최초 파지 시간 초과, 재시도, 100ms 연속 판정, 정상 낙하·착지, 배치 슬롯 분리, 정산 중복 방지, 할인 수익 동등성 확인.
- GPU: 64환경 고정 액션 및 구성한 낙하/착지 장면, 15,360전이. 자세한 결과는 `integration.json`.
- 원본 소스 349개 파일 해시 일치. 기존 release·정책 체크포인트·Plane에는 변경하지 않았다.
- 남은 비용 정산은 지정한 고정 비용 잔여 구간과 할인 수익이 같다. GAE·가치함수 손실 분포 및 학습 성능이 같다는 뜻은 아니다.

원본 SHOW-76, GitHub SHOW-100 성공본, 기존 실험 코드·가중치를 변경하지 않았다.

## 합의한 실행 조건

- 다음 학습은 새 MLP로 처음부터, 4,096환경. 초기화 4개는 40/20/20/20%.
- 보상 구간은 접근 / 파지·들기 / 운반 / 낮은 해제 / 안착·철수·A 복귀의 5개.
- 초기에는 각 시작점의 대표 물체·그리퍼 자세/배치를 고정하고 동역학 DR만 적용한다.
  자세·위치 다양화와 관측 랜덤화는 후속 난이도로 별도 기록한다. 가까운 놓기 초기화 없음.
- 현재 DLS+QP v=1rad/s, a=5rad/s², jerk=100rad/s³와 TCP 행동 배율 0.1m/s·0.5rad/s 유지 예정.
- 그리퍼는 SHOW-100의 열기/유지/닫기·최종 목표 관측·기존 개폐 속도 제한을 사용한다.
  팔/그리퍼 순차 조정기를 추가하지 않는다. 실제 제어 연결은 이번 수식 구현 범위 밖이다.
- 물리 5ms / 정책 100ms, 에피소드 20초. 성공 즉시 종료하지 않고 실제 완료 상태를 평가한다.
- A=[0,0.523,-0.450,0,0,0]rad. 각 관절 오차 3° 이하·최대 관절 속도 0.05rad/s 이하를
  200ms 유지하고 안착·접촉 없는 여유 80mm도 만족해야 최종 완료. 그리퍼 폭은 완료 조건에서 제외.

## 주 보상 — 원본 +5/+2에 추가하지 않고 대체

거리 m, 각도 rad, 시간 s. 아래 수식을 현재 실제 구간 하나에만 적용한다.
초기화 번호는 수식의 입력이 아니며 중간 초기화도 관측된 접촉·시간으로 판정한다.

기호: d=TCP–큐브 거리, x=큐브–그릇 중심 XY 거리, z=그릇 내부 바닥 기준 TCP 높이,
g=clip(양쪽 손가락 접촉 유지 시간/0.1,0,1), l=clip(큐브 실제 아랫면–탁자 높이/0.02,0,1).

| 구간 | 주 보상 | 다음 구간 진입 조건 |
| --- | --- | --- |
| 접근 | 1−tanh(5d) | d≤20mm 또는 실제 손가락 접촉 |
| 파지·들기 | 1+0.5g+0.5gl | 양쪽 접촉 100ms와 물체 아랫면 높이 20mm |
| 운반 | 2+[1−tanh(5x)] | 파지 유지, x≤50mm, 물체 중심이 그릇 테두리 위 |
| 놓기 준비 | 3+0.5[1−tanh(e/0.04)] | 실제 첫 해제와 아래의 높이·수평·열기 조건 |
| 안착·철수·복귀 | 4+0.25s+0.25c+0.5a (게이트는 아래 참고) | 안착·여유·A 정지 유지 완료 |
| 완료 유지 | 5 | 현재 완료 조건 유지 |

높이 오차 e=max(0.05−z,z−0.06,0). 이 항은 **그릇 위까지 운반한 이후만** 사용한다.
운반 중 높이 벌점과 깔때기 항은 없다. 잡은 채 주 보상은 3.5를 넘지 않고, 실제 해제가 있어야 4가 된다.

- s=clip(해제 후 그릇 내부 바닥 접촉·상대 병진 속도≤20mm/s 유지 시간/100ms,0,1).
- c=clip(TCP의 큐브·그릇 여유/80mm,0,1). 재접촉한 정책 스텝에는 c 항을 지급하지 않는다.
- a=clip(1−최대 관절 A 오차/1rad,0,1). s=1, c=1, 재접촉 없음일 때만 지급한다.
- A에 근접했어도 속도·200ms 조건이 없으면 주 보상 상한은 4.99다. 완료 시 5.
- 복귀 정지 시간은 100ms 안착 확인 뒤부터 센다. 큐브가 다시 움직이면 완료 판정도 해제된다.
- 이미 들어 올린 물체를 정상적으로 낮추는 것은 과거 들어 올리기 진척을 취소하지 않는다.
  반면 잘못 해제하거나 그릇 밖 탁자에 떨어뜨린 경우에는 과거 단계 점수를 유지하지 않고 주 보상 0.

## 실제 해제와 시간 기록

- 5ms마다 실제 양쪽 손가락 접촉을 확인하고, 운반 후 두 접촉이 모두 사라진 구간의 첫 상태를 기록한다.
- 접촉 상실 20ms가 지속되면 실제 해제로 확정한다. 첫 접촉 상실 직전 TCP 높이 50~60mm,
  큐브–그릇 중심 오차≤17mm, 열기 의도가 있어야 합격 해제다.
- 열기 의도는 새 OPEN 요청뿐 아니라 이미 저장된 OPEN 목표에 따른 진행 중 개방도 포함한다.
- 해제 직전 TCP·큐브 속도는 각각 기록하지만 판정의 속도 제한이나 명령 차단에는 사용하지 않는다.
- 착지 직전 큐브 하강 속도를 별도 기록한다. 이번에는 별도 충격 벌점을 추가하지 않는다.
- 높은 곳에서 놓은 뒤 나중에 낮게 재접촉·재파지해도 최초 해제 자격을 복구하지 않는다.
- 합격 해제 후 실수로 재접촉한 경우에는 −0.5를 주되, 이후 자연스럽게 철수·복귀하여 회복할 수 있다.

## 보조 항과 비용

| 항목 | 수식·상한 | 활성화 |
| --- | --- | --- |
| 큐브 면 정렬 | 0.5×0.5(1+cos(4Δyaw))×exp(−d/0.03)×(1−g) | 파지 전만. 확인 보상 +0.5가 증가하는 만큼 보조 항을 감쇠해 파지 순간 점수 하락 방지 |
| 수평 정렬 | +0.5/100ms | 운반·놓기 준비 중 x≤17mm. 해제 뒤 종료 |
| 저속 유지 | +0.5/100ms 창, 에피소드 최대 2회 | 파지 운반 이력·그릇 위 도달 후, x≤17mm·z=50~60mm·TCP 상대 속도≤10mm/s |
| 큐브 밀림 비용 | 0.5×clip(큐브 수평 속도/0.05,0,1) | 파지 확인 전만. 운반·낙하 제외 |
| 재접촉 비용 | −0.5/정책 스텝 | 해제 후 5ms 표본 중 로봇–큐브/그릇 접촉이 한 번이라도 존재. 지속시간 비례 아님 |
| 행동 비용 | −0.001Σa² | 정규화 행동 7개 |
| 행동 변화 비용 | −0.01Σ(a−a_prev)² | 정책 스텝 사이의 정규화 행동 7개 |

최종 보상=주 보상+면 정렬+수평 정렬+이번 창의 저속 보너스−밀림−재접촉−행동−행동 변화.
접근 보상은 해제 뒤 존재하지 않으며, 옛 SHOW-100 내부 진입 +5·해제 +2와 중복 합산하지 않는다.
저속 보너스 수령 횟수는 왕복·파지 상실·재파지로 초기화하지 않는다. 기술적 비유한 입력은 −1로 표시한다.
각 구간의 범위와 보조 항의 활성 구간에 의해 기본 설정의 보상은 스텝당 최대 5다.
20초 총 무할인 보상 상한 1,000, γ=0.99 할인 보상 상한 약 433이다. 총점이 5라는 뜻이 아니다.

## 검증과 구현 경계

`stage_reward.py`는 JAX jit/vmap 가능한 순수 함수다. 환경·체크포인트·SDK를 불러오지 않는다.
start_interval → 5ms advance_memory 20회 → reward_terms 1회의 호출 계약을 사용한다.
원시 Features는 정책 입력으로 추가하지 않는다. 실제 MJX 센서·초기화 연결은 다음 단계다.

```bash
JAX_PLATFORMS=cpu PYTHONPATH=src:runtime/src python -m pytest -q tests/test_stage_reward.py
JAX_PLATFORMS=cpu PYTHONPATH=src:runtime/src python scripts/show103/audit_stage_reward.py --output docs/show103/stage-reward-v1/audit.json
```

검증은 실제 수식에 합성 상태 이력을 넣어 대기·늦은 해제·높은 해제·왕복·재파지·재접촉을 비교한다.
동일 20초·동일 γ, 기존 행동 비용과 보조 항도 포함한다. 가능한 로봇 경로나 학습 성공률의 증명은 아니다.
4,096개 배치 검사는 **보상 수식·이력 갱신의 CPU 연산**이며 4,096환경 GPU 물리 검증이 아니다.
구체 수치와 판정은 [audit.json](stage-reward-v1/audit.json), [validation.json](stage-reward-v1/validation.json)에 기록한다.

## 후속 학습과 난이도 기록

첫 성공 확인 후 위치 범위 → 물체/그리퍼 상대 방향·파지 깊이 → 파지한 관절 자세 순서로 한 종류씩 확대한다.
각 확대는 직전 좋은 정책에서 이어 학습하고, 원래 조건과 확대한 조건의 초기화별 전체 완료율을 분리한다.
난이도 수준마다 데이터 범위·체크포인트·동역학/관측 DR·누적 전이·승급/중단 근거를 기록한다.
승급 임계값과 실제 reset bank는 이번 수식 구현으로 실행된 것이 아니다.
